# 中期答辩 PPT 说明

> 成品：[`校园活动与社团管理_中期答辩.pptx`](../校园活动与社团管理_中期答辩.pptx)（15 页）
> 生成脚本：[`scripts/pptx/build_midterm_ppt.py`](../scripts/pptx/build_midterm_ppt.py)

## 1. 汇报结构

按「已经做出来的东西 → 踩过的坑 → 后面 6 周怎么干」组织，对应老师最关心的三件事。

| 页 | 内容 |
| --- | --- |
| 1 | 封面：前 6 周把「发布 → 报名 → 名单」跑通 |
| 2 | 今天讲什么：三个问题 |
| 3 | 前 6 周：原计划 vs 实际做出来的 |
| 4 | 三条线总览：30 个接口、6 张表、4 个页面、0 超报 |
| 5 | 手机端：四个页面 + 页面结构示意 |
| 6 | 服务器端：四块分工 + 报名检查顺序 |
| 7 | 数据库：发布 → 报名 → 看名单，6 张表、三道保险 |
| 8 | 最难的一关：同时报名不超名额 + 测试结果 |
| 9 | 测试：正常、边界、出错情况 |
| 10 | 踩过的坑：6 个问题、5 个已解决 |
| 11 | 还没做完的 + 可能影响进度的 |
| 12 | 第 7–9 周：消息、统计、管理员功能 |
| 13 | 第 10–12 周：停止加功能、测试、上架 |
| 14 | 每周怎么配合 + 想请老师指导的三个问题 |
| 15 | 结尾 |

每页都写了**演讲备注**，在 PowerPoint 的「备注」里可以看到，照着讲即可。

## 2. 语言风格

面向大二学生，尽量少用术语：

- 不写「端侧 / 云侧」，写「手机端 / 服务器端」；
- 不写「幂等键 / 事务 / 并发 / TOCTOU」，写「防重复编号 / 一起成功或失败 / 同时报名」；
- 不写「接口契约 / DTO / Repository / 状态机」，写「接口格式 / 接口数据 / 负责读写数据库的代码 / 状态变化规则」；
- 保留必须出现的名字：鸿蒙、仓颉、ArkTS、数据库、Excel、华为应用市场。

## 4. 重新生成与检查

依赖：`python-pptx`、`lxml`。

```powershell
py -3.13 -m pip install python-pptx lxml
py -3.13 scripts/pptx/build_midterm_ppt.py 校园活动与社团管理_中期答辩.pptx
```

> 本机 Python 3.14 alpha 的 `lxml` 加载会失败，请用 `py -3.13`。

导出 PNG 检查排版（Windows + PowerPoint）：

```powershell
$ppt = New-Object -ComObject PowerPoint.Application
$pres = $ppt.Presentations.Open("...\校园活动与社团管理_中期答辩.pptx", $true, $false, $false)
$pres.Export("...\render", "PNG", 1600, 900)
$pres.Close(); $ppt.Quit()
```

## 5. 答辩时怎么讲

1. **先给结论**：前 6 周的计划都完成了，完整流程能现场演示。
2. **再给证据**：手机端四个页面、服务器端四块、数据库三道保险，最后落到「50 人同时抢 10 个名额，成功刚好 10 人」。
3. **主动讲坑**：仓颉工具崩溃、重复报名误报、加锁顺序、手机端名额不同步——每个都讲「怎么发现、怎么解决、留下了什么测试」。
4. **最后讲计划**：第 7–9 周补功能，第 10 周停止加功能，第 11 周候选版本，第 12 周提交上架，留 1 周缓冲。
5. **请老师拍板**：中期演示范围、上架材料、统计范围。

如果老师追问「为什么不用更简单的做法」，回答：

> 报名不是表单收集，最怕的是名额多一个或少一个。我们把判断和扣减放在一条数据库语句里，再用唯一限制和防重复编号兜底，这样不依赖程序员每次记得加锁。
