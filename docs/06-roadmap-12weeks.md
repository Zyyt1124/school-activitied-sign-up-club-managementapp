# 12 周开发计划

> 三人团队，按技术栈切分，但**每个人都要能跑通自己负责的链路**。
> 接口契约 W2 冻结，W6 最小闭环，W10 功能冻结，W12 提交审核。

## 1. 角色

| 角色 | 负责 | 关键产出 |
| --- | --- | --- |
| A · 端侧 | ArkTS 页面、组件、交互、端侧缓存、无障碍 | 可演示的 HarmonyOS 应用 |
| B · 仓颉业务 | 领域模型、状态机、权限、报名 / 活动 / 社团服务、API 门面 | 可测试的业务内核 |
| C · 数据与联调 | 数据库、SQL 适配器、事务、部署、安全、上架材料 | 稳定的数据层 + 可上架版本 |

> 分工不是隔离：A 要会看 API 契约，B 要会写 SQL，C 要能跑通端侧 demo。
> 每周至少一次全员联调，避免「三份进度、三套接口」。

## 2. 周计划

### W1 · 立项与技术验证

| 角色 | 任务 |
| --- | --- |
| A | 需求细化、页面原型、交互流程、设计 token |
| B | 仓颉 1.0.5 + DevEco 26 + SDK 26 环境验证；领域模型草案 |
| C | 数据库选型、ER 图、云环境与账号、隐私政策草稿 |

**交付**：原型图 + 技术选型结论 + ER 图。
**验收**：三个人都能在本机编译 `app/` 和 `server/` 的最小工程。

### W2 · 契约与骨架

| 角色 | 任务 |
| --- | --- |
| A | 登录 / 首页骨架、`ApiClient`、`SessionStore`、错误态 |
| B | 领域模型、状态机、`Outcome` / `BizError`、Repository 接口 |
| C | DDL、索引、seed 数据、内存仓储、迁移脚本规范 |

**交付**：`docs/03-api-contract.md` 冻结；端侧能登录并拉活动列表（可 mock）。
**验收**：字段、错误码、角色矩阵三方确认；`scripts/build.ps1` 通过。

### W3 · 登录与活动浏览

| 角色 | 任务 |
| --- | --- |
| A | 活动列表 / 详情、加载 / 空态 / 错误态、下拉刷新 |
| B | 登录、Token、角色权限、社团创建 / 审核 |
| C | SQL 适配器骨架、参数化查询、`TxRunner` 事务封装 |

**交付**：可登录并浏览活动；社团创建→审核→展示跑通。
**验收**：`student` / `leader` / `admin` 三个账号看到不同入口。

### W4 · 社团与入社

| 角色 | 任务 |
| --- | --- |
| A | 社团列表 / 详情、入社申请表单、我的社团 |
| B | 活动草稿 / 发布 / 状态机、权限守卫、入社审核 |

**交付**：社团创建→审核→展示→入社申请跑通。
**验收**：越权操作返回 `FORBIDDEN`；状态机非法流转被拒绝。

### W5 · 活动发布与报名

| 角色 | 任务 |
| --- | --- |

**交付**：发布→报名→取消可演示。
**验收**：同一幂等键重试不重复扣名额；重复报名返回 `ALREADY_SIGNED`。

### W6 · 最小闭环

| 角色 | 任务 |

| B | 并发 / 幂等测试、错误码统一 |
| C | 并发压测、慢查询与索引修正、压测报告 |

**交付**：**最小闭环**——发布 → 报名 → 查看名单。
**验收**：50 并发抢 10 个名额，成功数 = 10，无超报；P95 延迟可接受。

### W7 · 消息与提醒

## 4. 风险与预案

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| 仓颉工具链问题 | 编译 / 运行受阻 | 保留 `scripts/build.ps1` 兜底；必要时换机器 / 用 DevEco 工具链；不把宏作为关键路径 |
| 接口契约反复 | 端侧返工 | W2 冻结；变更走 PR；只做加法 |
| 并发 / 幂等测试不足 | 超报、重复报名 | W5 开始压测；唯一索引 + 条件 UPDATE 双保险 |
| 上架审核周期 | W12 来不及 | W11 内测分发；材料提前到 W9；预留 1 周缓冲 |
| 三人时间冲突 | 进度延误 | 每周例会；任务拆到 2–3 天粒度；关键路径提前 |
| 范围膨胀 | 最小闭环延期 | W6 未达最小闭环就砍可选功能（评论、收藏、地图、热度） |

## 5. 完成定义（Definition of Done）

一个功能算完成，需要同时满足：

- 端侧：正常 / 加载 / 空 / 错误四种状态都有；
- 云侧：参数校验、权限校验、错误码、事务边界都有；
- 数据：索引 / 约束 / 迁移脚本都有；
- 契约：`docs/03-api-contract.md` 与两端 DTO 同步；
- 测试：至少一个正常用例 + 一个边界 / 失败用例；
- 演示：能在模拟器 / 真机上走通；
- 文档：README 或对应 docs 更新。

## 6. 每周例会清单

1. 上周交付物 demo（不是口头汇报）；
2. 本周接口 / 字段变更（必须当场确认）；
3. 阻塞项与风险（谁负责、什么时候解决）；
4. 下周任务拆到人 / 天；
5. 代码互审安排。
